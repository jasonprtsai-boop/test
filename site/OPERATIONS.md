# 常見異常處理與操作手冊

日期：2026-10-19。涵蓋目前可辨識的常見狀況；無法保證列舉所有硬體／作業系統故障。

## 先判斷這三件事

1. 有人身危險、碰撞或動作失控：先用實體 Emergency Stop。網站停止只能阻止後續命令。
2. 只有頁面斷線：先查看監控與最新狀態。頁面逾時不代表命令取消，不連點開始／執行／重試。
3. 機械已停止但棋局出錯：保存現場與照片，再按下表處理；不要先刪 game.json、改棋色或重播機械命令。

## 啟動、網頁與環境

| 狀況／訊息 | 檢查位置與處理 | 能否直接繼續 |
| --- | --- | --- |
| 網站完全打不開 | 確認在 site 目錄，以 .venv Python 執行 app.py；查看啟動終端及「系統紀錄/system.log」 | 修復啟動原因後再開頁 |
| 缺套件、ImportError、版本不合 | 使用網站 .venv 與 requirements.lock；不要混用其他 Python | 修復環境並重啟 |
| 8000／5000 被占用、website.lock／hardware.lock 衝突 | 關閉已知舊網站或直接連線工具，確認是否仍有 Robot 動作；不要任意刪鎖檔繞過保護 | 確認單一控制程序後重啟 |
| 無法建立 runtime 或寫入 game.json | 確認資料夾權限、磁碟空間、同步軟體／防毒鎖定 | 安全快照不能寫入時禁止動作 |
| 磁碟低於 1 GiB，預檢不通過 | 備份並移走已結束的舊局影像，保留當前局；確認空間後重啟重新預檢 | 通過預檢才開始 |
| hardware 未啟用 | 有人值守且完成現場檢查後，以 TMCHESS_HARDWARE_ENABLED=1 啟動 | 未啟用時只能查看 |
| 系統準備中 | 查看 monitor 中未通過的具體項目；預檢例外會顯示原因並重試 | 不連點開始 |
| Base／TCP 未確認 | 在 TMflow 核對 RobotBase／NOTOOL，監控台完成本次確認 | 不要只按確認而不看實機 |
| 瀏覽器斷線／狀態更新中斷 | 等待自動重連；確認 app 仍執行、本機位址與網路 | 對局留在後端，開頁不重設 |
| 請求 10 秒逾時 | 查監控與最新狀態；命令可能已接收 | 不能因逾時就重送機械動作 |
| 多個玩家頁或監控頁 | 同用後端單一狀態。控制變更仍可能來自其他頁，避免多人同時操作 | 網頁不會各自建立獨立對局 |
| 409 busy／不允許此操作 | 查當前 phase 與按鈕；另一個命令尚未結束，或安全條件不符 | 等待或依明確錯誤處理 |
| 403 Origin／415 JSON | 從 http://127.0.0.1:8000 或 localhost 的網站操作；檢查用的程式也須依 API 規則送出 | 不要放寬來源保護 |
| 按鈕看似不能操作 | 先看監控：忙碌、無有效盤面、預檢未過、pending 或動作未知都會影響控制 | 原因未解除前不要繞過後端 |

## 拍攝、辨識與棋盤

| 狀況／訊息 | 檢查位置與處理 | 能否直接繼續 |
| --- | --- | --- |
| 等待 V1 逾時 | 確認 TMflow 已啟動、拍攝路徑、相機、上傳 URL 的 LAN IP:5000、Robot IP 與防火牆 | 機械靜止確認後再續局／拍攝 |
| 已收到一張但 V2 逾時 | 看第一個 External Image Processing 是否收到成功回覆、流程是否走到第二節點 | 不把 V1 當完整棋盤 |
| `$CPERR,2,F1` | TMflow 未進 Listen；檢查是否停在 Vision 或其他節點、流程會否回 Listen | 等 Listen 就緒，不盲目重送移動 |
| source_ip_not_allowed／JPEG／413 | 核對 Robot IP、multipart JPEG、大小限制；勿以空白或其他格式冒充成功上傳 | 修復來源後重拍 |
| 未啟動拍攝或多出第三張 | 上傳不在有效窗口，可能是遲到／重送影像 | 不手動塞入舊照片當本次結果 |
| YOLO 缺模型／類別集合不符 | 核對根目錄 best.pt 與程式定義、套件環境 | 更換正確模型後重新檢查 |
| YOLO 載入／推論逾時或程序退出 | 查 system.log；隔離程序會被終止，下次有效拍攝重新建立 | 先確認機械停止，再走恢復流程 |
| 能唯一判定哪顆棋移動，其他格漏棋／錯色／多棋 | 系統以最後確認盤面套用該步，補回其他誤辨識格；引擎確認合法後提交。Excel 拍攝表列出原始錯誤與修正明細 | 可繼續；原始影像仍保存 |
| 找不到起點、終點棋子也不確定 | 原始辨識無法提供走子證據；改善光線、遮擋、棋子位置後重新拍攝 | 不猜走法 |
| 有兩種以上可能走法／同時移兩枚棋子 | 系統暫停。以保存盤面與照片人工核對、還原多餘移動 | 不能用歷史覆蓋來掩蓋多次移動 |
| 唯一走法但不合法 | 還原玩家走子；核對盤面方向與棋子辨識 | 不提交，也不讓 AI 接著動作 |
| AI 起點仍有棋／終點錯／吃子未完成 | pending 保留；查看影像與現場。按重新落子會先重拍：完成則提交，仍是落子前盤面才重試 | 部分完成需人工還原／檢查 |
| AI 的其他格誤辨識但端點清楚 | 需唯一走子與 pending 相符，才可用前一盤面補回其他格 | 不跳過端點證據 |
| 沒有有效基準的新棋盤辨識失敗 | 初始盤面不能借用其他局或猜補；改善拍攝後再建局 | 不適用歷史修正 |
| 圖片顯示與內部盤面不同 | 有可能是歷史修正；看「歷史修正明細」與原始 result.json | 不修改原圖來偽裝辨識成功 |

## 機械、停止與續局

| 狀況／訊息 | 檢查位置與處理 | 能否直接繼續 |
| --- | --- | --- |
| Robot 網路中斷、Pose 讀取失敗 | 確認控制器、IP、Listen 與線路；先確認實體停止 | 動作未知時不得直接重試 |
| XYZ 到點但姿態不符／未穩定 | 查 Pose、Base／TCP 與目標；誤差或穩定樣本未過會中止後續命令 | 不放寬容差來隱藏問題 |
| 吸盤未吸住／放下 | DO 回覆只代表接受命令，沒有真空感測證據；靠雙視角與現場確認 | 不以 DO 成功當棋子搬移成功 |
| 吸盤關閉無法確認 | 系統保持動作未知；由操作員確認實體停止與吸盤狀態 | 不能只重啟解除 |
| 按網站停止 | 停止後續流程，當前控制器已接受的動作可能繼續 | 危險時用實體 Emergency Stop |
| 停止後按鈕仍鎖定 | 等待工作結束；查看動作未知狀態 | 現場確認停止後才可明確解除 |
| 程式或電腦在動作中斷 | 重啟後保留未知動作鎖；先查看現場與監控，再確認停止 | 不自動重播 pending |
| 重新開網頁 | 應保留同一 game-id、回合與紀錄 | 不用建立新局 |
| 重新啟動後繼續上一局 | 核對實棋並選正確回合；系統重拍、重播歷史核對 | 同盤面不能任意改行棋方 |
| 關機期間玩家已走一步 | 選 AI 回合；只有從保存盤面能辨識唯一合法玩家著法才補記並繼續 | 歷史提交後才轉 AI |
| 續局選錯回合或盤面不符 | 系統拒絕且保存原行棋方；改選正確回合或核對現場 | 不會把選項當成已發生的棋步 |
| pending 已完成／未完成／部分完成 | 分別是：核對後提交、不重算引擎；停在明確重試；人工檢查 | 不盲目重播 |
| 舊 JSON 損壞、備份復原、不完整歷史 | 保留檔案；備份載入也鎖定真機。若不能重播，使用目前棋盤建立新基準 | 不猜補歷史或手改安全旗標 |
| 想保留目前實棋但不沿用錯誤歷史 | 停止並確認安全後，從目前棋盤開始新局、指定玩家棋色與行棋方 | 舊局留存，新基準無更早局史 |
| 無合法著法／引擎判定結束 | 顯示結果，保存紀錄。需新一局時選新開局 | 結束局不作一般續局 |
| 開局、重複、長將等規則爭議 | 核對初始盤面＋完整 UCI 歷史與實際引擎版本 | 新基準無法還原更早歷史 |

## Excel 與對局紀錄

| 狀況 | 處理 | 證據／限制 |
| --- | --- | --- |
| Excel 被開啟而無法更新 | 關閉該檔案，背景約 5 秒後重試最新快照 | 不重送 Robot 動作 |
| Excel 已存在但顯示更新中／失敗 | 先看監控狀態；下載可能仍是上一版，修復權限／空間／占用後再下載 | 存在不代表最新 |
| Excel 目錄不可寫 | 修復權限與容量，保留網站可查看；背景重試 | game.json 仍是安全資料，不能一併放寬保存失敗 |
| 沒看到逐步盤面 | 新版看「棋盤履歷」，初始為第 0 步，每個已提交著法各一盤 | pending 不算已提交 |
| 想追查辨識補了哪些格 | 看拍攝表的「原始盤面檢查」「沿用歷史格數」「歷史修正明細」及對應影像編號 | 格位採 UCI；保留原始觀察數字類別 |
| 摘要顯示歷史不一致 | 依報告定位行棋方、FEN 或盤面差異；不要把匯出成功當對局正確 | 舊錯誤不能自動證明真實歷史 |
| 缺少初始盤面 | 可能建局未完成；無法憑最後盤面還原已遺失著法 | 標示缺少，不填假歷史 |
| 對局結束後 Excel 還沒寫好 | 稍候背景輸出；若失敗看監控原因。程式重啟可由最新安全快照重建 | 不影響已提交棋步 |
| 需重匯出舊局 | 使用下方工具，輸出到全新的目錄 | 原始檔不覆寫 |
| 手動編輯 Excel | 先另存副本；系統下一次背景更新可能覆蓋系統產生檔 | Excel 修改不會反寫到棋局 |
| 長期累積影像與紀錄 | 定期備份已結束局，再人工管理容量；不要刪使用中的局 | 目前無自動清理策略 |

## 只讀檢查與重新匯出

在 site 目錄執行，預設只讀 JSON、列出統計，不連線 Robot：

```powershell
.\.venv\Scripts\python.exe tools\audit_game_records.py --report runtime\record-audit.json
```

重新匯出副本時指定已存在的完整 game-id 與**尚不存在**的輸出資料夾：

```powershell
.\.venv\Scripts\python.exe tools\audit_game_records.py --game-id 20261019T122551Z-38ab667b --export-dir outputs\reexport-reviewed
```

工具會揭露原始紀錄問題，不會修正 JSON、猜補棋步、解除安全鎖或下機械命令。若輸出目錄已存在會拒絕執行，防止無意覆蓋。

game-id、發生時間、當時按的操作、監控錯誤代碼／訊息、對應 capture-id、現場是否已停止、實棋與畫面差異。保留該局 game.json、相關圖片／result.json 及該時段 system.log。先確認這一步是否已提交或仍是 pending，再決定續局或重試。
