## 已確認且修復的問題

所有下列問題的信心為 **CONFIRMED**；程式位置與對應測試是證據，不以先前 AI 的判斷為依據。

| 等級 | 根因與程式位置 | 原本可能的結果 | 修復與直接驗證 |
| --- | --- | --- | --- |
| P1 | `service._player_done`、`_perform_ai_turn`、各回合／結束判斷在引擎回傳後缺少停止檢查 | 停止後仍提交玩家棋步；STOPPED 被改回 PLAYER_TURN、ENGINE_READY 或 FINISHED | 外部查詢不持有服務鎖；接受結果時在同一把鎖中重新確認未停止。已確認後提交的棋步保留，停止後才回來的結果作廢 |
| P1 | 錯誤恢復又失敗時的 fallback 直接發布 ERROR | 操作員已停止，晚到的恢復讀檔錯誤仍會覆蓋 STOPPED | 另一次先失敗再修復的回歸證實此路徑；錯誤發布與停止核對共用鎖，恢復檔案 I/O 留在鎖外 |
| P1 | `_record_persistence_failure` 無條件清除 busy，連停止保存失敗也一樣 | 舊工作仍在執行，卻能開始新局、清除 stop event，污染同一份狀態 | 增加忙碌鎖釋放責任：尚未排入工作的建立失敗可釋放；停止保存失敗由原工作結束時釋放。測試同時確認新開始被拒絕 |
| P1 | `_restore_session` 未交叉核對 pending move 的 UCI、座標、吃子、前後盤面 | 不一致的保存資料可能進入重新拍攝／重試 | 恢復前先驗證全部關聯，重播預期盤面；保存棋步再經引擎合法性檢查後才進拍攝。錯誤資料不先寫入執行中盤面 |
| P1 | 保存的 `engine_vs_engine` 可夾帶 `execution_mode=automatic`，或模式與控制者矛盾 | 略過逐步確認的設計，恢復成未授權的連續模式 | 對局模式、控制者、玩家／AI 棋色與執行模式交叉核對，不一致直接拒絕 |
| P1 | reset-page API 只檢查 busy，未拒絕正在等待玩家的活躍對局 | 即使網頁不再自動呼叫，直接請求仍可清掉活躍對局 | 活躍回合必須先停止；測試確認被拒絕後 game-id 與盤面不變 |
| P2 | `StateStore.update` 直接改原字典，mutator 拋例外時未回復 | 修改了一半卻沒有 revision、通知或可追蹤提交 | 先在副本執行，成功後才交換狀態。故意改 phase／機械旗標再拋錯，確認原資料與版本完全不變 |
| P2 | `session._read_snapshot` 將任意 phase 丟入 set 判斷 | 合法 JSON 但 phase 是 list／dict 時，TypeError 會越過損壞快照處理，阻斷啟動 | 先檢查型別；交由既有備份／SessionCorruptionError 與安全鎖處理 |
| P2 | `load_latest` 同秒遊戲依隨機 UUID 字典排序 | 快速連續建局後可能選到較舊局 | 先按建立秒，秒內按安全快照檔案時間排序；測試刻意讓新 UUID 小於舊 UUID |
| P2 | 已 close 的服務仍開放開始等 API | 工作排到已死亡的執行緒，永久 busy／無回應 | 全部控制關閉；後端拒絕新命令，不能只靠 UI 停用。close 保持可重複呼叫 |
| P2 | UI 直接套用每個到達的回應，沒有版本核對 | 慢到的舊命令回應覆蓋新的停止狀態／按鈕 | 玩家與監控共用版本挑選器；每次服務啟動有獨立 instance_id，允許重啟後版本歸零並拒絕已退休服務的回應 |
| P2 | 安全停止確認的一條分支直接呼叫 Excel 排程 | JSON 已成功保存，卻因非必要 Excel 例外回報確認失敗、記憶體再鎖定 | 統一經隔離排程方法；測試核對磁碟與記憶體的停止確認一致，Excel 錯誤仍顯示 |
| P3 | worker 在初始化驗證完成前啟動；關閉 sentinel 未 task_done | 初始化失敗留下等待執行緒；關閉後佇列計數不歸零 | 初始化成功才啟動；每個取出的項目都結算。close 後確認沒有未結算項目 |

相關修正另將「正常停止」記為取消，不再記成工作故障；Base／TCP 重複確認不再覆蓋進行中的棋局訊息。`get_state` 在服務鎖內同時取得狀態與可用控制，減少舊狀態混上新按鈕的機會。

## 關鍵不變條件

1. **busy 的擁有者是目前工作。** 停止或保存失敗不能讓另一局提前進入。
2. **外部結果不是立即提交。** 引擎、辨識回傳後，必須與停止／關閉狀態一起核對。
3. **已提交歷史不能被停止撤銷。** 停止發生前已驗證及提交的棋步保留；晚到結果不再建立新提交。
4. **pending 不是已完成棋步。** UCI、起終點、吃子、落子前及預期盤面必須相符；恢復不能變更執行模式。
5. **JSON 安全狀態優先於 Excel。** 報表失敗不能重送 Robot 命令，也不能讓安全確認呈現磁碟／記憶體矛盾。
6. **較晚抵達不代表較新。** UI 同時核對服務身分與 revision。

## 停止競態的修復邊界

```text
背景工作送出引擎查詢（服務鎖已釋放）
                ↓
操作員按停止 → 設 stop event、保存 STOPPED
                ↓
引擎稍後回傳
                ↓
取得服務鎖 → 發現已停止 → 取消接受結果
                ↓
原工作結束、發布最終狀態、釋放 busy
```

接受結果與提交使用同一把服務鎖；長時間引擎查詢沒有包進該鎖。同步磁碟保存仍可能影響 API 等待，作業系統／磁碟永久卡住不是本次軟體測試能排除的故障。
