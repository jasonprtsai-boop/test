## 架構與資料責任

```text
玩家／監控頁
  → localhost Flask API（Waitress）
  → 單一 GameService／StateStore
  → 序列化背景工作
      → TMRobotAdapter（Listen、Pose、吸盤）
      → TMvision receiver → 雙視角檔案 → 隔離 YOLO 程序
      → Pikafish UCI 子程序
  → game.json 同步安全快照（原子替換／備份）
  → Excel 背景輸出（可失敗、重試，不授權機械動作）
```

已提交盤面與著法歷史是後續推理的基準。新影像是一次觀察；pending move 是尚未驗證完成的動作，不能當作已提交著法。Excel 是報告，續局不從 Excel 讀取盤面。

## 安全、效能與維護檢查

- 控制服務仍限 localhost，控制 POST 要求 JSON 與正確 Origin；沒有擴張既有授權或網路範圍。
- 影像結果不是動作完成證明；Robot 仍須 Listen／Pose 確認。沒有修改座標、速度、吸盤或既有安全鎖。
- YOLO 模型載入／推論與 Pikafish 等待有期限；照片與動作各階段也有限時。整個回合可包含多次限時階段，不能把單次推論上限誤當回合總上限。
- Excel 每次匯出重建整本，逐步盤面約為每步 90 格，屬線性成長。未進行千步或多日磁碟耗用壓力測試；長期影像與紀錄仍需人工備份／容量管理。
- 偵測到多個可能走子會暫停。單一影像若把真實物理變化辨識成其他噪音，歷史修正仍可能無法分辨；操作者一次只移一枚棋子是使用前提。
- 沒有新增資料庫、登入、模型或部署架構；沒有以例外吞掉安全快照失敗。JSON 無法保存仍須阻擋後續動作。
