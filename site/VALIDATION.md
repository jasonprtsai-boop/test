## 2026-10-30：引擎設定 API 來源保護回歸

- 已確認問題：`/api/engine/depth` 與 `/api/engine/movetime` 未包含在控制 POST 的來源保護範圍，不受信任 Origin 仍回傳 200。
- 修正：將 `/api/engine/` 納入既有 JSON 與本機 Origin 檢查；不改動機械控制或引擎設定範圍。
- 驗證：完整 272 項測試在 ResourceWarning 視為錯誤下通過；新增缺少 Origin、外部 Origin、null Origin、錯誤連接埠與非 JSON 請求的拒絕及設定不變檢查。既有合法請求及數值範圍測試通過。compileall 與 pip check 通過。
- 下表的 174 項為歷史驗證紀錄；本次測試數以本節為準。
- 結論：此 API 缺口回歸 PASS；不代表已完成全系統漏洞稽核或真機安全驗證。

## 2026-10-20：平移後 V2 影像座標修正

- 根因：V2 仍使用舊像素格點，將紅炮與兩顆紅兵分配到錯格；三次新局皆產生相同 6 格差異。V1 對應格點在此次照片中未出現差異。
- 依據：`20261020T114718Z-bf93cad0`、`20261020T114815Z-f10fb2ec`、`20261020T114843Z-9eba5ffd` 的原始照片與 YOLO 偵測；以可見格線校正 V2，未以標準盤面覆寫辨識結果。
- 決策：2592×1944 V2 影像的四列 X 改為 1030／1287／1545／1805，四行 Y 改為 1037／1295／1547／1800；接管範圍與容許距離維持原值。
- 驗證：三組照片重新推論後均還原完整標準盤面；原始偵測保存於 `tests/fixtures/translated_board_detections.json` 作回歸資料。這只驗證此次影像映射，未實測後續真機落子，亦不代表所有空格已有放置棋子的實測。

### Pikafish 退出原因追查

- `20261020T115235Z-17caa472` 的保存盤面重現引擎退出碼 1；引擎原文為 `Unsupported position. WHITE pawn(s) on invalid positions.`，其前綴 `info string CRITICAL ERROR:` 原先未被 adapter 辨識。
- 同局照片使用校正後 V2 映射重新推論，可正常取得黑方 `bestmove b7e7`；未送出機械命令。保存的舊盤面未被覆寫。
- Adapter 現在保留 CRITICAL ERROR 原因，對兵／卒不合法位置增加中文提示。31 項引擎與視覺測試通過，包含真實引擎拒絕錯位紅兵及下一次合法搜尋恢復。
